# 方法論

`context-memory` 的目標很單純:留下足夠的脈絡,讓未來的你、或是一個 AI agent,可以在不用重新聽一次整個討論的情況下,接續一個主題。

留存的最小單位叫**記憶項目(memory item)**。它可以是一個專案、主題、決策、計畫、調查中的問題、風險,或是被擱置的任務——不需要等到「最終決定」才值得記下來。

## 兩段式流程

### 1. 快速捕捉

在一場討論剛結束、或你只有幾分鐘的時候使用(對應網頁介面的[快速捕捉](web-tour.md)頁)。

即使細節還不完整,也應該先建立項目;最多問三個問題,而且只問「答案很可能很快就會被忘記」的問題。

最基本、必須留下的欄位:

- 標題
- 一段式摘要(snapshot)
- 為什麼這件事重要
- 目前的理解
- 下一步行動,或是「什麼情況該回來看這個項目」的觸發點
- 還沒解決的問題
- 之後回來找這個項目時,能用來搜尋的關鍵字

### 2. 全面補充

在同一天稍晚、或是在這個主題「冷掉」之前使用(對應網頁介面項目詳情頁的「AI 補齊」動作)。

補齊這張「防止知識蒸發」的檢查清單:

- **背景**:這個主題是怎麼被觸發的?
- **關係人**:誰知道什麼?
- **現況**:現在的事實是什麼?
- **期望的結果**:什麼樣的狀態算是有進展?
- **決策**:決定了什麼、提議了什麼、否決了什麼、擱置了什麼?
- **理由**:為什麼當時的想法說得通?
- **考慮過的替代方案**:還考慮過哪些做法?為什麼沒選?
- **限制**:時間、預算、相容性、團隊、組織政治、維運上的限制。
- **假設**:有哪些「假設是真的」但其實可能是錯的?
- **風險**:之後可能會出什麼問題?
- **佐證**:連結、檔案、記錄、訊息、工單、對話紀錄。
- **下一步行動**:如果知道的話,寫清楚由誰、做什麼、什麼時候。
- **回想線索**:未來的你會用什麼關鍵字、什麼事實去搜尋這個項目。

網頁介面的「AI 補齊」就是在幫你把這張清單填好;決策、理由、替代方案、後果這幾個帶有歷史意義的欄位不會被直接覆寫——舊內容會被保留下來,接在新內容後面並標上日期(見[網頁功能導覽](web-tour.md))。

## 信心標記

每個項目的內容,都應該區分:

- **已知(Known)**:直接說出來的,或親眼觀察到的事實。
- **推論(Inferred)**:合理的推測或解讀。
- **未知(Unknown)**:重要但還缺的資訊。

這個區分很重要,因為 LLM 很擅長幫你把設計背後的理由補回來,但也可能在不確定的地方過度腦補。

## 狀態值

一個記憶項目會處於以下狀態之一(網頁介面的「總覽」頁就是依這些狀態分組):

| 狀態 | 意思 |
| --- | --- |
| 快速捕捉(capture-quick) | 剛快速建立,內容還不完整。 |
| 待補齊(needs-enrichment) | 重要到值得盡快補完。 |
| 進行中(active) | 目前正在進行的工作或討論。 |
| 等待中(waiting) | 被別人或某個外部事件卡住。 |
| 擱置(parked) | 刻意先放著,之後再回來看。 |
| 已完成(done) | 沒有後續動作,單純保留作記憶。 |
| 已取代(superseded) | 被另一個項目取代。 |

「已完成」與「已取代」是終態,不會被算進「總覽」頁與陳舊提示的統計裡;其餘五種都是非終態,長時間沒更新會被標記為陳舊。
